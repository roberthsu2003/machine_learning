## 💡 為什麼採用「程式儲存格 ＋ AI 互動儲存格」的設計？

人資人員在學習機器學習時，最常遇到兩大困擾：
1. 完全讓 AI 從無到有自由寫程式，常因模型隨機性、套件版號衝突或語法報錯，導致學習卡關挫折。
2. 傳統程式教材只有代碼，沒有人解釋「為什麼人資數據要這樣分析」。

因此，本範例採用了最穩健的高品質學習架構：
1. **保證可執行的穩定基底**：我們已經在 [員工離職風險預警_分類篇.ipynb](./員工離職風險預警_分類篇.ipynb) 中為你依序寫好了標準的機器學習程式儲存格（經過完整測試，絕無語法報錯）。
2. **段段有解說**：每個程式儲存格的**正下方**，都緊接著一個專屬的文字儲存格，以 HR 實務白話詳細說明「這段程式在做什麼」。
3. **內建豐富的 AI 伴學對話小抄 (Prompt)**：每個步驟依據非工程師應該掌握的核心觀念，提供多個不同角度的提問提示詞（包含招募重置成本、特徵倫理陷阱、滿意度分數解讀與程式碼客製修改），你可以自由挑選並複製貼給 Copilot / ChatGPT！

## 📊 資料集介紹 (`hr_turnover.csv`)

📥 **資料集位置**：本機相對路徑 [`hr_turnover.csv`](./hr_turnover.csv)

本數據集記錄了企業歷年 1,800 位員工在職考評、工作負荷與離職狀態：

| 欄位名稱 | 數據型態 | 數值範例 / 類別 | 人資業務實務意涵 |
| :--- | :--- | :--- | :--- |
| **所屬部門** | 類別型 (`object`) | 研發工程、業務銷售、行銷企劃、客戶服務、財務人資 | 團隊性質與市場挖角熱門度 |
| **年資_年** | 數值型 (`float64`) | 3.0 (年，範圍 0.5~12 年) | 在公司服務年限（2~3 年常為轉職高原期） |
| **月薪_TWD** | 數值型 (`int64`) | 65,000 (元，範圍 3 萬~16 萬元) | 固定底薪待遇 |
| **過去一年加班時數** | 數值型 (`int64`) | 320 (小時，範圍 20~480 小時) | 衡量身心過勞與工作負擔客觀指標 |
| **最近一次績效評等** | 類別型 (`object`) | 特優(A)、良好(B+)、符合預期(B)、需改善(C) | 年度考核評定等級 |
| **最近升遷距今年數** | 數值型 (`float64`) | 3.0 (年) | 職涯晉升通道是否受阻之指標 |
| **工作滿意度評分** | 數值型 (`int64`) | 2 (分，範圍 1~5 分) | 匿名問卷滿意度自評 |
| **是否離職 (目標 y)** | 類別型 (`object`) | **「是」 / 「否」** | **預測目標變數（二元分類）** |

## 🖥️ 進階專題：餵資料給 AI，打造獨立桌面預測 App (`app.py`)

在真實人資管理中，你不需要把整個 `ipynb` 的代碼全部搬過去。當你掌握了基本觀念後，你可以**直接把手邊的人資資料結構餵給 AI**，讓 AI 替你撰寫獨立運作的桌面視窗預測工具 (`app.py`)。

但是，**新手最忌諱讓 AI「自作主張、一口氣吐出整份代碼」**，因為那樣你根本不知道 AI 擅自做了哪些假設。

因此，我們設計了這份**「優良的伴學諮詢式 Prompt」**：
- 它強制 AI 扮演**耐心的技術顧問**，嚴禁直接噴出程式碼！
- 當 AI 遇到重要的機器學習決策時，**必須主動用白話詢問你，而且每次提問都必須先向你解釋：「為什麼我身為 AI 必須這樣問你？這在機器學習代表什麼意思？」**
- 透過一問一答，你既能釐清人資需求，又能理解模型設計本質，最後產出完美的桌面 App！

### 📋 複製給 AI 的專屬【新手伴學諮詢 Prompt】

```text
你是一位專為「零程式背景、剛接觸機器學習的企業人資 (HRBP)/管理主管」服務的資深 AI 機器學習架構師與導師。

我現在手邊有一份資料集，我希望最終由你為我寫出一個單一、獨立、開箱即用的 Python 桌面視窗應用程式（`app.py`，使用 Python 內建的 Tkinter 或 PyQt）。

【我的人資資料說明】
資料檔案：`hr_turnover.csv`（企業歷年員工在職特徵與離職紀錄）
資料欄位如下：
- 所屬部門（研發工程、業務銷售、行銷企劃、客戶服務、財務人資）
- 年資_年（數值型，如 3.0 年）
- 月薪_TWD（數值型）
- 過去一年加班時數（數值型）
- 最近一次績效評等（特優(A)、良好(B+)、符合預期(B)、需改善(C)）
- 最近升遷距今年數（數值型）
- 工作滿意度評分（1~5 分）
- 是否離職（是、否）

⚠️【極度重要規則：請絕對不要直接給我程式碼！】
因為我是機器學習新手，如果你直接給我整份程式碼，我無法理解背後的決策邏輯。
在動手寫程式碼之前，請你扮演「親切耐心的專業顧問」，依序向我確認關鍵問題。
並且，**你提出每一個問題時，都必須嚴格遵循以下「解說式提問格式」向我說明**：

--------------------------------------------------
【提問格式規範】
👉 問題 X：[你要問我的具體問題]
💡【為什麼我要這樣問你？（大白話解釋）】：[請用生活化白話向非工程師說明：為什麼演算法無法自己決定這件事？背後的資料科學原因是什麼？]
📌【建議選項與人資影響】：
   - 選項 A：...（說明若選此項，在人資實務或模型上的影響）
   - 選項 B：...（說明若選此項，在人資實務或模型上的影響）
--------------------------------------------------

請針對以下四個核心面向逐一向我提問，並附上白話解釋：

1. 【確認預測目標 Target / y】
   - 請告訴我：為什麼機器學習演算法分不出誰是「員工在職表現（特徵）」、誰是「我們要預警的結果（是否離職）」？
2. 【檢查是否有作弊欄位或倫理偏誤】
   - 請告訴我：為什麼如果把「離職交接清單完成日」或「員工離職面談紀錄」放進去訓練，會造成嚴重的「資料洩漏（偷看答案）」？另外，年齡與性別等敏感個資在演算法中應如何謹慎處理以符合勞基法？
3. 【權衡人資留才成本（Precision vs. Recall）】
   - 請告訴我：「漏抓了真正想離職的核心骨幹而措手不及（漏報）」，與「把暫時有怨言但不想走的員工誤判為高風險而多排一次關懷面談（誤報）」，哪一個對企業的損失代價更高？這在召回率 (Recall) 門檻上代表什麼？
4. 【桌面 App 的操作體驗與防呆設計】
   - 請告訴我：既然是給人資主管與部門主管在辦公室評估團隊使用，為什麼介面必須內建「快速預測範例情境按鈕」？以及評估結果該如何提供客製化的留才行動指引？

請立刻開始扮演顧問向我提問，等待我的回覆後，才進行 `app.py` 的程式碼撰寫！
```
