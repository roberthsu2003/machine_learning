## 💡 為什麼採用「程式儲存格 ＋ AI 互動儲存格」的設計？

餐飲經營者在學習機器學習時，最常遇到兩大困擾：
1. 完全讓 AI 從無到有自由寫程式，常因模型隨機性、套件版號衝突或語法報錯，導致學習卡關挫折。
2. 傳統程式教材只有代碼，沒有人解釋「為什麼餐飲營收預測要這樣考慮天候變數」。

因此，本範例採用了最穩健的高品質學習架構：
1. **保證可執行的穩定基底**：我們已經在 [門市每日營收預估_迴歸篇.ipynb](./門市每日營收預估_迴歸篇.ipynb) 中為你依序寫好了標準的機器學習程式儲存格（經過完整測試，絕無語法報錯）。
2. **段段有解說**：每個程式儲存格的**正下方**，都緊接著一個專屬的文字儲存格，以餐飲店長白話詳細說明「這段程式在做什麼」。
3. **內建豐富的 AI 伴學對話小抄 (Prompt)**：每個步驟依據非工程師應該掌握的核心觀念，提供多個不同角度的提問提示詞（包含剩食報廢成本、客單價換算、天候影響權重與程式碼客製修改），你可以自由挑選並複製貼給 Copilot / ChatGPT！

## 📊 資料集介紹 (`store_revenue.csv`)

📥 **資料集位置**：本機相對路徑 [`store_revenue.csv`](./store_revenue.csv)

本數據集記錄了餐飲門市歷年 1,100 個營業日的天氣、商圈客流與最終營業額成效：

| 欄位名稱 | 數據型態 | 數值範例 / 類別 | 餐飲門市業務實務意涵 |
| :--- | :--- | :--- | :--- |
| **商圈型態** | 類別型 (`object`) | 信義商務區、西門觀光區、板橋住宅區、內科園區 | 門市客群結構（上班族商務客 vs 週末家庭客） |
| **星期別** | 類別型 (`object`) | 星期一 到 星期日 | 週期性客流循環 |
| **是否為國定假日** | 類別型 (`object`) | 是、否 | 國定連假與補班日變動 |
| **天氣狀況** | 類別型 (`object`) | 晴朗多雲、晴朗炎熱、局部陣雨、大雨滂沱 | 影響民眾出門聚餐意願之天候變數 |
| **最高氣溫_度C** | 數值型 (`float64`) | 28.0 (度，範圍 12~38 度) | 氣溫對冷飲、火鍋或特定菜色之驅動力 |
| **商圈活動熱度** | 數值型 (`int64`) | 80 (分，範圍 10~100 分) | 週邊展覽、百貨週年慶或演唱會聚集人潮 |
| **當日訂位客席率** | 數值型 (`float64`) | 0.85 (即已預訂 85% 客席，範圍 0.1~1.0) | 晨間已知之確定基本盤客流 |
| **每日營收_TWD (目標 y)** | 數值型 (`int64`) | **245,000 (元)** | **預測目標變數（連續數值迴歸）** |

## 🖥️ 進階專題：餵資料給 AI，打造獨立桌面預測 App (`app.py`)

在真實餐飲管理中，你不需要把整個 `ipynb` 的代碼全部搬過去。當你掌握了基本觀念後，你可以**直接把手邊的營業與氣象資料結構餵給 AI**，讓 AI 替你撰寫獨立運作的桌面視窗預測工具 (`app.py`)。

但是，**新手最忌諱讓 AI「自作主張、一口氣吐出整份代碼」**，因為那樣你根本不知道 AI 擅自做了哪些假設。

因此，我們設計了這份**「優良的伴學諮詢式 Prompt」**：
- 它強制 AI 扮演**耐心的技術顧問**，嚴禁直接噴出程式碼！
- 當 AI 遇到重要的機器學習決策時，**必須主動用白話詢問你，而且每次提問都必須先向你解釋：「為什麼我身為 AI 必須這樣問你？這在機器學習代表什麼意思？」**
- 透過一問一答，你既能釐清門市排班需求，又能理解模型設計本質，最後產出完美的桌面 App！

### 📋 複製給 AI 的專屬【新手伴學諮詢 Prompt】

```text
你是一位專為「零程式背景、剛接觸機器學習的餐飲店長/連鎖督導」服務的資深 AI 機器學習架構師與導師。

我現在手邊有一份資料集，我希望最終由你為我寫出一個單一、獨立、開箱即用的 Python 桌面視窗應用程式（`app.py`，使用 Python 內建的 Tkinter 或 PyQt）。

【我的餐飲營運資料說明】
資料檔案：`store_revenue.csv`（門市歷史天候、活動與每日營收資料）
資料欄位如下：
- 商圈型態（信義商務區、西門觀光區、板橋住宅區、內科園區）
- 星期別（星期一 到 星期日）
- 是否為國定假日（是、否）
- 天氣狀況（晴朗多雲、晴朗炎熱、局部陣雨、大雨滂沱）
- 最高氣溫_度C（數值型，12~38 度）
- 商圈活動熱度（數值型，10~100 分）
- 當日訂位客席率（數值型，如 0.85 代表 85% 已訂位）
- 每日營收_TWD（連續數值型，如 245,000）

⚠️【極度重要規則：請絕對不要直接給我程式碼！】
因為我是機器學習新手，如果你直接給我整份程式碼，我無法理解背後的決策邏輯。
在動手寫程式碼之前，請你扮演「親切耐心的專業顧問」，依序向我確認關鍵問題。
並且，**你提出每一個問題時，都必須嚴格遵循以下「解說式提問格式」向我說明**：

--------------------------------------------------
【提問格式規範】
👉 問題 X：[你要問我的具體問題]
💡【為什麼我要這樣問你？（大白話解釋）】：[請用生活化白話向非工程師說明：為什麼演算法無法自己決定這件事？背後的資料科學原因是什麼？]
📌【建議選項與餐飲營運影響】：
   - 選項 A：...（說明若選此項，在門市排班或備料上的影響）
   - 選項 B：...（說明若選此項，在門市排班或備料上的影響）
--------------------------------------------------

請針對以下四個核心面向逐一向我提問，並附上白話解釋：

1. 【確認預測目標 Target / y（迴歸問題）】
   - 請告訴我：為什麼這次我們要預測的營業額是連續數值（迴歸），而不是預測「達標 vs 未達標」（分類）？這如何幫助店長計算食材採購斤數與兼職工讀生時薪預算？
2. 【檢查是否有作弊欄位或打烊後的資訊】
   - 請告訴我：為什麼如果把「當天收銀機開出的發票張數」或「當晚廚餘報廢重量」放進去預估當天營收，會造成嚴重的「資料洩漏（偷看答案）」？
3. 【權衡預測誤差對食材耗損與人力的影響（高估 vs 低估）】
   - 請告訴我：「預估營收過高導致多叫了容易腐壞的生鮮肉品海鮮而報廢虧損（正誤差）」，與「預估營收過低導致備料不足客人點不到菜甚至缺人傳菜客訴（負誤差）」，這在餐飲業該如何平衡？
4. 【桌面 App 的操作體驗與防呆設計】
   - 請告訴我：既然是給店長在每天下午排班或叫貨時使用，為什麼介面必須內建「快速預測範例情境按鈕」？以及評估結果該如何呈現內外場兼職排班人數與備料建議？

請立刻開始扮演顧問向我提問，等待我的回覆後，才進行 `app.py` 的程式碼撰寫！
```
