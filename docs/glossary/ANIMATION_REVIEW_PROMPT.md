# 網頁動畫檢查與改善：AI 交接 Prompt

請在這個 GitHub 專案中，完整檢查並修正機器學習教學網頁的動畫。請直接執行檢查與必要修改，不要只提供建議或閱讀程式碼就宣稱完成。

## 教學目標與背景

這些網頁是台灣教師教學使用的教材。學生從 GitHub README 進入章節，以按鈕和 2D 幾何動畫理解原本難以用靜態圖片說明的觀念。

目前有 12 章、42 個名詞解釋動畫，主要位於 `docs/glossary/`。此外，`docs/index.html` 是原有簡報教材，也有動畫。請一併清點與檢查，實際場景數以目前程式和頁面為準。

教師最重視的是「學生看得懂」。動畫即使沒有程式錯誤，如果不知道怎麼操作、不知道圖形代表什麼，或比靜態圖更難理解，仍是需要修正的問題。

## 必須保留的要求

- 保留 12 章原有順序、四大模組與核心教材內容。
- 採 Light Mode、繁體中文，使用台灣學生容易理解的用語。
- 第 01 章名稱為「機器學習的類型」，比較場景稱「學習類型比較」，不要恢復成「學習範式」。
- X 表示整份特徵矩陣、y 表示真實標籤、ŷ 表示預測結果。單一特徵可用 X₁、X₂；若使用小寫 x 或向量記法，要明確解釋。分類圖的兩個特徵軸不能把其中一軸標成標籤 y。
- 使用真正可觀察的 2D 幾何變化：點移動、方塊重排、曲線或分界變化、資料流向等。只有數字跳動或裝飾效果不算完成教學動畫。
- 全部發布資源放在 `docs/`，沿用 GitHub Pages 的 `/docs` 設定。保留已有章節網址與場景錨點，避免破壞 README 入口。
- 不要將概念示意、參數插值或預設分數說成真實模型訓練結果。能實際計算的場景，圖形、數值與解釋必須一致。
- 不要自行 commit、push 或部署；完成修改後交付檢查報告與待提交的檔案。

## 先理解檔案結構

請先閱讀專案適用的 `AGENTS.md`（若有），再閱讀：

- `docs/glossary/README.md`：維護與本機預覽方法。
- `docs/glossary/chapters.json`：12 章與場景清單、原教材位置。
- `名詞解釋/README.md` 與各章 README：教學內容、章序、原圖。
- 各章的 `scenes/index.js`、`lesson.js`。
- `docs/glossary/shared/player.js`、`geometry.js`、`math.js`、`fitting.js`、`scene.js`、`lesson.css`。
- `docs/glossary/build.py`：從 Markdown 與 metadata 產生 HTML。
- `docs/index.html`、`course.js`、`motion.js` 及相關樣式：既有簡報網頁與動畫。

不要只修改生成的 HTML，卻讓下一次產生器執行時覆蓋修正。教材文字改來源 README，場景資訊改 metadata，動畫改場景程式，必要時改產生器，再重新產生頁面。

## 已知問題與最近的修正

第 01 章「監督式：分類與回歸」曾有以下問題：

- 座標軸畫了兩次，刻度與文字重疊。
- 圖上的 y 軸實際是第二個特徵，造成標籤與特徵混淆。
- 分界線自行移動，但沒有清楚交代移動的意義與操作順序。
- 起點就顯示預測，混淆「已知標籤」和「模型預測」。

目前已改成房屋面積例子：X₁ 是面積（坪），y 是房屋類型或成交價。畫面有操作指南，起點先看資料，第一次按「下一步」顯示模型，第二次顯示新房屋的預測 ŷ。請實際驗證這個流程，並以相同清晰度要求檢查其他場景；不用強迫所有場景採相同的步數或版型。

## 每個場景都要檢查

### 1. 教學清晰度（最高優先）

站在第一次學習的學生角度，回答：

1. 這個場景只要教會我哪個觀念？
2. 每個點、方塊、線、箭頭、顏色與形狀代表什麼？
3. X、y、ŷ 分別在哪裡？座標名稱與單位是否正確？
4. 起點呈現什麼？第一個要按的按鈕是什麼？
5. 下一步改變了什麼？為什麼改變？終點應得到什麼結論？
6. 學生改一個參數，能否說出畫面變化的原因？

如果無法從頁面本身回答，就補上簡短的操作指引、圖例、階段標題或解釋，必要時簡化場景。優先使用具體例子與單位，不要堆更多抽象點或複雜動畫。

### 2. 操作與時間軸

- 初始、播放中、暫停、重設、單步和終點狀態都要檢查。
- 檢查速度、時間軸前後拖動、重播、放大與返回、Esc、重抽資料（有提供才檢查）。
- 所有下拉選項、滑桿最小／中間／最大值、核取方塊都要實際操作。
- 改參數後，畫面與解釋是否同步？如果回到起點，是否明確告訴學生下一步？
- 可拖曳場景要檢查滑鼠與觸控，包含邊界位置。
- 離開畫面、切換分頁、返回後的暫停與恢復行為是否合理？
- 單步是否對應有意義的教學階段？不能讓學生連按多次卻看不出差異。

### 3. 數值與模型

- 分別辨認實算、概念示意、預設情境與過程插值，確認說明與程式一致。
- 獨立核算代表案例，不要只用程式自己的輸出驗證自己。
- 特別檢查：資料切分互斥、資料洩漏、縮放器只 fit Train、距離與投票、梯度方向、學習率、集成與 OOF、混淆矩陣、ROC/AUC、MAE/MSE/RMSE、R²、交叉驗證及 Batch／Iteration／Epoch。
- 檢查分母為零、常數標籤、負 R²、同票、最後不足一批、過大步長、圖形超出座標等邊界情況。
- 圖形比例要有意義。若截斷、限幅或只是示意，必須明講；例如誤差平方塊的面積不能暗中封頂卻仍聲稱按比例表示。
- 查證不確定的概念時優先使用官方文件或原始研究，於報告記錄來源。

### 4. 版面、可讀性與發布

- 實際查看桌面與手機版，至少測試約 1440px 和 390px 寬度。
- 檢查重複座標軸、刻度重疊、文字遮住點、圖形被裁切、畫面縮小後字太小等問題。
- 不能只靠顏色分辨類別，要有形狀、圖例或文字可對照。
- 檢查鍵盤操作、按鈕／滑桿標籤與可閱讀的文字解釋。
- 檢查公式、表格、原圖、章節導覽、README 連結與所有場景錨點。
- 在 `/machine_learning/` 子路徑發布時，相對路徑仍須正確，不得依賴只在本機存在的檔案。
- 檢查瀏覽器 console、載入失敗、缺失圖片與 JS 模組匯入。

## 執行與驗證方式

在專案根目錄可使用：

```sh
.venv/bin/python docs/glossary/build.py
node docs/glossary/check-math.mjs
python3 -m http.server 8765 --directory docs
```

瀏覽 `http://localhost:8765/glossary/` 與 `http://localhost:8765/`。若環境沒有相同虛擬環境，先確認產生器依賴；不要擅自更改全域 Python 環境。

請使用可用的真實瀏覽器工具（例如 Playwright）操作與截圖。自動化可清點場景、找載入錯誤、驗證按鈕與數值；但每個場景仍須視覺檢查與教學判讀。截圖可以比較起點、中間和終點，不能只看像素是否改變就認定學生能理解。

原有數值檢查通過不代表所有動畫都正確。修正後測試受影響的場景；修改共用播放器或繪圖工具時，再檢查其他章節是否退化。不能執行的檢查，應明列限制，不得宣稱已通過。

## 交付成果

1. 完成必要的程式、教材與網頁修正。
2. 在 `docs/glossary/ANIMATION_REVIEW_REPORT.md` 儲存報告。
3. 報告要逐一列出所有場景，包括既有簡報動畫；使用表格：

   | 章節／頁面 | 場景 ID 與網址 | 教學目標 | 發現的問題 | 修正內容 | 驗證方法與結果 | 尚未解決事項 |
   | --- | --- | --- | --- | --- | --- | --- |

4. 區分「已實際測過」「已修正並複測」「尚未驗證」，不要把未檢查場景標為通過。
5. 記錄瀏覽器、畫面尺寸、數值案例、測試指令與截圖位置；截圖放在 `output/animation-review/`，避免把暫存工具檔散放在專案根目錄。
6. 最後簡短告訴教師：哪些問題最影響理解、做了哪些改善、驗證結果與剩餘限制。保留變更供教師審閱，不自行提交或發布。

完成標準：所有場景都有檢查紀錄；已知問題完成修正與複測；學生可以從頁面知道怎麼操作、看什麼與學到什麼；數值與圖形一致。若有無法處理的項目，明確記錄原因與後續工作。
