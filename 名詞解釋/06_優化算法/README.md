# 6. 優化算法 (Optimization)

---

### 梯度下降法 (Gradient Descent)

**描述**：  
一種核心的數值優化算法，通過計算損失函數（Loss Function）的梯度（斜率）來迭代更新模型參數，目標是找到讓損失函數最小化的參數組合。

![梯度下降法原理與變體對比](images/01_gradient_descent.png)

**運作原理**：
1. **計算梯度**：計算損失函數對各參數的偏微分（梯度 ∇J(θ)）。
2. **反向更新**：沿著梯度的反方向（最陡峭下降方向）前進更新參數。
3. **持續迭代**：重複步驟直到梯度接近於 0 或達到收斂條件。

**核心更新公式**：  
$$\theta = \theta - \alpha \cdot \nabla J(\theta)$$  
*(其中 $\theta$ 為參數，$\alpha$ 為學習率，$\nabla J(\theta)$ 為損失函數的梯度)*

**三種常見變體**：
- **批次梯度下降 (Batch GD)**：每次迭代使用「全部」訓練數據。路徑最平滑直達谷底，但數據量大時計算極慢。
- **隨機梯度下降 (Stochastic GD)**：每次迭代僅隨機抽取「單一」樣本。計算飛快，但路徑劇烈震盪波動。
- **小批次梯度下降 (Mini-batch GD)**：每次迭代抽取一小批樣本（如 32、64 筆）。兼具速度與穩定性，為現代深度學習最常用首選。

### 學習率 (Learning Rate, $\alpha$)

**描述**：  
決定模型參數在梯度方向上「每次更新跨步大小」的超參數。

![學習率大小對訓練收斂的影響](images/02_learning_rate.png)

**步長大小的影響**：
- **學習率過小**：每步前進極慢，需要極多輪迭代才能收斂，耗費大量時間與運算資源，且容易卡在局部極小值（Local Minima）。
- **學習率適中**：能夠平穩且快速地步步趨近並達到全局最佳解（Optimal Loss）。
- **學習率過大**：步子跨得太大，容易在谷底兩側劇烈反彈震盪，甚至數值發散（Divergence），完全無法收斂。

**常見調整與選擇策略**：
- 從典型值開始嘗試（如 $0.001$、$0.01$）。
- **學習率調度器 (Learning Rate Scheduler)**：前期使用較大步長快速接近，後期隨訓練輪數衰減以精確落入最優點。
- **自適應優化器**：如 Adam、RMSprop 等會針對不同維度參數動態調整學習步長。

### 批次大小 (Batch Size)

**描述**：  
在小批次梯度下降中，模型進行一次參數更新時所使用的訓練樣本數量。

![批次大小權衡與民調抽樣比喻](images/03_batch_size_comparison.png)

**批次大小的權衡比較**：
- **大批次 (如 256、512)**：
  - **優點**：梯度估計精確、訓練過程穩定、能充分發揮 GPU 並行計算效能。
  - **缺點**：消耗龐大 GPU 記憶體，且有時容易收斂在較尖銳的局部極值，泛化能力略遜。
- **小批次 (如 16、32)**：
  - **優點**：記憶體需求極低；更新震盪具有噪聲正則化效果，容易跳出鞍點或不良局部盲點。
  - **缺點**：梯度震盪較大、無法充分吃滿 GPU 滿載吞吐量。

> 💡 **直覺理解「批次大小」的影響（民調比喻）**：
> - **批次大（像全國大規模民調）**：一次問上萬人，誤差極小、結果穩定（訓練穩定）；但動員資源多，記憶體 (RAM/VRAM) 負擔沉重。
> - **批次小（像街頭隨機抽訪 5 人）**：問話速度極快，記憶體消耗極低；但若剛好遇到 5 個極端意見者，決策方向就會晃動劇烈（訓練波動）。不過，這種「搖晃跳動」偶爾正好能幫模型震出盲點，找到更好的全局最優解！

**實務常見選擇**：$32$、$64$、$128$、$256$（通常設定為 2 的次方以配合 GPU 硬體架構加速）。
