# 💼 機器學習模型部署：薪資預測-多元線性迴歸 (FastAPI + Gradio)

本專案是一個特別為機器學習教學設計的**實務部署範例**。它展示了如何將**多元線性迴歸模型**從訓練、預處理、序列化儲存、建立 RESTful API，到設計網頁互動 UI，最後一鍵部署至雲端平台（如 Render）的完整生命週期。

---

## 🎯 本課教學目標

學習完本專案，你將掌握以下核心技術：
1. **多元特徵預處理**：學會區分順序型變數（使用 `OrdinalEncoder` 對「學歷」進行位階編碼）與名目型變數（使用 `OneHotEncoder` 對「城市」進行獨熱編碼），並以 `StandardScaler` 進行特徵標準化。
2. **預處理器序列化**：理解為何在部署時需要將 `OrdinalEncoder`、`OneHotEncoder`、`StandardScaler` 與模型一同打包序列化，以避免推理時特徵尺度與順序不一致的資料洩漏或錯誤。
3. **高可讀性 API**：使用 `FastAPI` 建立具備 `Pydantic` 強型別校驗與資料過濾機制的薪資預測端點。
4. **模型擬合優化與 $R^2$ 解析**：理解為何錯用 `LabelEncoder` 會導致模型 $R^2$ 只有 ~0.221，以及如何改用 `OrdinalEncoder` 將 $R^2$ 提升至 **0.846+**。
5. **三種迴歸演算法比較 (Linear / Lasso / Ridge)**：學會比較普通線性迴歸、Lasso 迴歸 ($L_1$ 正則化) 與 Ridge 嶺迴歸 ($L_2$ 正則化)，觀察正則化強度 $\alpha$ 對權重收縮與特徵選擇的影響。
6. **數學方程式動態解析**：在網頁 UI 動態將線性迴歸擬合出來的**權重係數 (Coefficients) 與截距 (Intercept)** 組裝成可讀的數學迴歸方程式，輔助學生直觀理解多元線性迴歸的數學原理。
7. **雲端網路優化**：理解反向代理（Reverse Proxy）下的緩衝與連線佇列問題，學會透過 `queue=False` 與 `.release()` 優化服務。

## 📖 核心觀念解析

### 1. 為什麼要保存 Preprocessors (預處理器)？
在機器學習的實際部署中，我們最常犯的錯誤是「只保存 Model 卻沒保存 Preprocessors」。
如果使用者的輸入是原始字串（如 `"大學"`, `"城市A"`），但模型需要的是經過標準化後的數值矩陣：
1. **類別對照一致性**：`OrdinalEncoder` 與 `OneHotEncoder` 在 `fit` 時決定的類別對應順序，必須完全與預測時一致。
2. **特徵縮放一致性**：預測時輸入的年資（例如 `5.3`）必須使用與**訓練集完全相同的均值與標準差**進行標準化。
因此，我們將 `model`、`oe`、`ohe`、`scaler` 打包在同一個字典中存成 `salary_model.joblib`，保證預測與訓練的管道 (Pipeline) 完全一致。

### 2. 🔍 核心診斷：為什麼原先模型的 $R^2$ 決定係數很低（僅約 0.221）？

許多學生在初學機器學習時，常不加思索地將所有文字特徵直接丟給 `LabelEncoder` 處理。然而在本範例中，這正是導致 $R^2$ 慘跌的核心元兇：

1. **`LabelEncoder` 的字典序問題**：
   原程式碼使用 `LabelEncoder` 時，它會按照中文字串的字典序排序：
   - `"大學"` $\rightarrow 0$
   - `"碩士以上"` $\rightarrow 1$
   - `"高中以下"` $\rightarrow 2$
2. **邏輯嚴重反轉**：
   線性迴歸模型會把編碼後的數字視為**具有連續數值大小意義**的特徵。上述編碼等於強制告訴模型：**「高中以下 (2) > 碩士以上 (1) > 大學 (0)」**，學歷越高的人在模型中得到的數值反而越低！
3. **優化解法（`OrdinalEncoder` 順序編碼）**：
   學歷屬於**順序型類別變數 (Ordinal Category)**。我們必須改用 `OrdinalEncoder(categories=[["高中以下", "大學", "碩士以上"]])`，顯式將學歷依程度賦予數值：
   - `"高中以下"` $\rightarrow 0$
   - `"大學"` $\rightarrow 1$
   - `"碩士以上"` $\rightarrow 2$

#### 💡 優化前後對照表

| 特徵處理方式 | 學歷編碼對應 | 訓練集 $R^2$ | 測試集 $R^2$ (random_state=76) | 學歷特徵權重 ($w_2$) |
| :--- | :--- | :---: | :---: | :---: |
| **原本方法** (`LabelEncoder`) | 大學=0, 碩士=1, 高中=2 (邏輯顛倒) | `0.499` | **`0.221`** | **`-1.607`** (錯誤減薪) |
| **優化後** (`OrdinalEncoder`) | 高中=0, 大學=1, 碩士=2 (正確位階) | `0.934` | **`0.846`** | **`+15.307`** (合理加薪) |

### 3. 多元線性迴歸的數學意義
多元線性迴歸模型學得的關係可以表示為：
$$Salary = w_1 \cdot YearsExperience + w_2 \cdot EducationLevel + w_3 \cdot City\_城市A + w_4 \cdot City\_城市B + w_5 \cdot City\_城市C + b$$
*   **$w_i$ (權重係數)**：代表在其他條件不變的情況下，該特徵標準化數值增加一個單位，薪資的增減變化（k / 千元）。
*   **$b$ (截距)**：代表基準值。

### 4. 🤖 三種迴歸演算法比較 (Linear vs. Lasso vs. Ridge)

本系統支援三種經典的迴歸模型，供學生切分與調校正則化強度 $\alpha$：

1. **普通多元線性迴歸 (Linear Regression / OLS)**：
   - 無正則化懲罰項，追求訓練殘差平方和最小。
   - 易受特徵間多重共線性影響。
2. **Ridge 嶺迴歸 ($L_2$ 正則化)**：
   - 損失函數加入 $L_2$ 懲罰項 $\alpha \sum w_i^2$。
   - 將所有特徵權重按比例平滑縮減，能有效減輕多元共線性並改善測試集泛化能力（本數據集 $R^2 \approx 0.855$）。
3. **Lasso 迴歸 ($L_1$ 正則化)**：
   - 損失函數加入 $L_1$ 懲罰項 $\alpha \sum |w_i|$。
   - 具備**稀疏性 (Sparsity)** 特質，會直接將冗餘或次要特徵的權重歸零，自動進行特徵選擇（本數據集將 `City_城市A` 權重歸零，使測試集 $R^2$ 提升至 **`0.899`**）。

#### 💡 三種模型實測對照表 (`test_size=0.2, random_state=76`)

| 迴歸演算法 | 正則化懲罰項 | 測試集 $R^2$ | `YearsExp` 權重 | `EduLevel` 權重 | `City_A` 權重 |
| :--- | :--- | :---: | :---: | :---: | :---: |
| **LinearRegression** | 無 | `0.8463` | `+5.696` | `+15.307` | `+0.566` |
| **Ridge (α=1.0)** | $L_2$ 平滑縮減 | `0.8552` | `+5.390` | `+14.464` | `+0.185` |
| **Lasso (α=1.0)** | $L_1$ 自動特徵選擇 | **`0.8994`** | `+3.846` | `+14.085` | **`0.000`** (已被歸零) |

## 🛠️ 本地實作指引

### 1. 環境準備與套件安裝
建議在專案目錄下使用虛擬環境執行，以避免套件衝突：
```bash
# 安裝依賴套件
pip install -r requirements.txt
```

### 2. 啟動服務
主程式 `app.py` 設有**自動化雙保險設計**：啟動時若在目錄下找不到模型檔 `salary_model.joblib`，會自動呼叫 `train_save.py` 進行訓練並存檔，保證服務絕不因缺少模型檔而崩潰。
```bash
# 本地直接啟動
python app.py
```
* **熱重載模式**：開發時如需修改代碼自動重啟，請使用：
  `RELOAD=true python app.py`
* **自訂 Port 啟動**：
  `PORT=3000 python app.py`

### 3. 本地測試與驗證

#### 🅰️ 測試網頁 UI
打開瀏覽器，訪問 `http://127.0.0.1:8000/`：
* 在 **「🔮 即時月薪預測」** 分頁中調整年資滑桿、學歷與城市下拉選單，並觀察預測薪資卡片的即時更新。
* 前往 **「⚙️ 線上模型訓練與公式解析」** 分頁，調整測試集分割比例後點擊「開始訓練」，查看決定係數 $R^2$、**迴歸方程式**與**特徵影響力長條圖**的即時變化。

#### 🅱️ 測試 FastAPI RESTful API 端點
開啟終端機，執行以下 `curl` 指令來測試我們的自訂 API 端點：

* **即時預測端點：`POST /predict`**
  ```bash
  curl -X POST http://127.0.0.1:8000/predict \
    -H "Content-Type: application/json" \
    -d '{"years_experience": 5.3, "education_level": "碩士以上", "city": "城市A"}'
  ```
  *回傳格式*：
  ```json
  {"predicted_salary":41.643073199564286,"estimated_annual_salary":583.0030247939}
  ```

* **線上訓練端點：`POST /train`**
  ```bash
  curl -X POST http://127.0.0.1:8000/train \
    -H "Content-Type: application/json" \
    -d '{"test_size": 0.2, "random_state": 76, "model_type": "Lasso", "alpha": 1.0}'
  ```

* **API 自動文件：`/docs`**
  打開瀏覽器造訪 `http://127.0.0.1:8000/docs`，即可在 Swagger UI 進行互動式 API 測試。

## 📝 課後練習與學生實驗指引

為了讓學生親身體會特徵工程對模型精確度的巨大影響，可設計以下實驗與延伸思考：

1. **重新訓練驗證精確度**：
   在 Web 介面的 **「⚙️ 線上模型訓練與公式解析」** 分頁，維持預設 `test_size=0.2` 與 `random_state=76` 點擊「🚀 開始訓練模型」。觀察指標卡片中的 $R^2$ 是否成功由修復前的 `0.221` 大幅提升至 **`0.846`** 以上！
2. **切換 Lasso 與 Ridge 比較正則化效果**：
   在網頁下拉選單選擇 `Lasso` 並設定 `alpha=1.0` 點擊訓練，觀察 `City_城市A` 的權重係數是否被直接歸零 ($0.0000$)，且測試集 $R^2$ 提升至 **`0.8994`**？這完美示範了 $L_1$ 正則化自動特徵選擇的能力。
3. **觀察權重方向性**：
   觀察「特徵影響力分析」圖表，檢查 `EducationLevel` 的權重係數是否轉為**強大的正向加薪 (+15.307)**？這是否符合「學歷越高等同薪資天花板越高」的真實經濟常識？
4. **測試不同測試集分割與 Alpha 調校**：
   嘗試調整 `alpha` 滑桿（如 0.1, 1.0, 5.0），觀察 $L_1$ 與 $L_2$ 正則化強度對 $R^2$ 與權重平滑程度的影響。
